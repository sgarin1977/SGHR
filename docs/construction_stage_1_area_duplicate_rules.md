# CON-005/CON-006: area duplicate preparation rules

Authority: rev.12 sections 6.4.1, 8.1 and 22; the customer's approved duplicate contract in new clarification.txt. The later duplicate clarification explicitly specifies copying active structural elements and geometry_json, fresh UUIDs, remapped parent IDs, draft state, naming in the current measurement, atomic storage and a duplicate audit. Historical measurement facts, photos, comments, verification/submission state and commercial links remain excluded.

This is a pure preparation step, not the duplicate service or endpoint. ConstructionAreaDuplicateContext carries typed tenant/project/measurement references; it does not authenticate, prove ownership, select a measurement or authorize a caller. The service must obtain and verify the real current measurement/project context, source linkage and effective access before calling the planner. measurement_id remains in operation context, not as a new column on permanent project_areas.

prepare_construction_area_duplicate validates the source tenant/project, non-deleted area, approved type/status, structural element fields and version-1 JSON geometry using existing domain validators. It ignores archived elements, fails for ambiguous IDs and invalid active parent graphs, and allocates fresh UUIDs for the area and copied active elements. WINDOW/DOOR/OPENING parents must be active copied WALL elements in the same source area. Parent links are rebuilt using the complete UUID map. Roots precede children in insertion order; stored sort_order values, including null and duplicates, are retained without renumbering.

The output contains explicitly listed structural data and internal source-ID provenance only. A new area is draft/row_version=1; each new element starts at row_version=1. Geometry uses independent deep copies and preserves unknown version-1 structural keys. No attributes for photos, historical measurement items/results, comments, audit, estimates/offers/documents, source timestamps/authors or verification/submission state are copied from source objects. New author/timestamps and the final audit must be supplied by the transactional service.

next_construction_area_copy_name uses the supplied occupied names from the selected measurement: original name + ' — копия', then the first available suffix starting at 2. It never searches all projects, chooses a measurement or enforces a global unique-name constraint. The transactional caller must load the complete relevant name set while protecting concurrent context changes. Preparation allocates new UUIDs on each call; API idempotency belongs to the future workflow, not this pure function.

Local tests cover all approved area types and source states, UUID separation, active/archived selection, parent remapping and ordering, retained nullable/duplicate sort orders, geometry isolation, whitelist exclusions, names and malformed inputs. They do not prove database transactionality, RLS, authorization, actual measurement membership, collision handling between concurrent requests or deployed HTTP behavior.

The installer adds this module, its tests and this document, preserving all existing application files. No new tables, fake measurement storage, migrations, HTTP routes, Supabase, Storage or real email operations are introduced. The actual duplicate implementation still needs real measurement_sessions/measurement_area_links dependencies, then repository/service/workflow/HTTP and database acceptance. Stage 1 remains open.
